# Предрегистрация: догоняющий лаг «BTC двинулся → альт ещё нет» (lead-lag)

Дата: **2026-10-23 04:40 MSK**. Данных под эту гипотезу не смотрели; часовые свечи в
`bt_cache` уже есть, новых скачиваний не нужно.

## Откуда идея

Из разбора живых ботов на Hyperliquid (Senpi, каталог из 135 стратегий): лаг BTC→альты
— отдельный архетип (`mantis` — «catchup/slipstream», `osprey` — «cross-asset lag», `cath`
— дисперсия). У нас этот класс **никогда не мерился**: все наши замеры были либо по
одной монете, либо кросс-секционно по 168ч.

Экономический смысл: BTC — ведущий актив по ликвидности; при резком часовом движении
часть альтов подтягивается с задержкой в 1–3 часа. Вопрос не «существует ли эффект»
(он известен в литературе), а «остаётся ли он после издержек на HL при нашем размере».

## Гипотезы

- **H4a (long-нога):** если BTC за последний час вырос на `z ≥ +2` своих 168-часовых
  σ, то альты, отставшие за тот же час (наименьший часовой доход среди топа по
  ликвидности), дают положительный средний доход за следующие 1/3/6 часов.
- **H4b (short-нога, зеркально):** при `z ≤ −2` отставшие вниз альты падают дальше.
  Проверяем, но помним: шорты у нас отключены по трём замерам, и для реальных денег
  short-нога потребует отдельного доказательства.

## Как считаем

- Данные: `bt_cache`, 52 монеты, 4763 часовых бара, окно 2026-03-22 … 2026-10-07.
- Универсум на каждый вход: **топ-20 по медианному часовому USD-объёму** за 30 дней
  до входа (ликвидность только из прошлого). BTC/ETH входят в универсум, но в
  кандидаты-«догоняющие» не берутся.
- Триггер: `z = r_btc_1h / σ_btc_1h(168)`, порог |z| ≥ 2, **не более одного входа в
  час** (берём самый большой |z|).
- Кандидаты: 3 альта с наименьшим часовым доходом на момент входа. Вход по закрытию
  бара t, выход по закрытию t+h, h ∈ {1, 3, 6}.
- Размер: равный нотионал $1000 на сделку (для сравнения между вариантами), P&L в
  процентах на сделку.
- Издержки: **0.115% на монету за круг** (0.045% тейкер + 0.0125% слиппедж на сторону,
  как в `TAKER_PCT` парного модуля). Плюс стресс **2× издержек** — обязательный тест,
  потому что §31 показал, что парная стратегия умирает уже при 2×.

## Критерии приёмки (до данных)

Вариант засчитывается только если **все** пункты выполнены для h, выбранного по
минимуму числа допущений (h=3 как основной; h=1 и h=6 — проверка на устойчивость):

- **N1:** средний нетто-доход на сделку > 0 при 1× издержках.
- **N2:** t-статистика среднего ≥ 2.0 (независимые сделки, консервативно).
- **N3:** прибыль-фактор ≥ 1.15.
- **N4:** обе половины периода положительны по нетто.
- **N5:** при **2× издержках** нетто на сделку остаётся > 0.
- **N6:** эффект не создан 5 лучшими сделками: убрать 5 самых прибыльных — нетто
  всё ещё > 0.

Если проваливается N5 — идея отклоняется без обсуждений, каким бы красивым ни был
эффект при 1×.

## Что это НЕ меняет

Живой код не трогаем (фриз до 31.10); это измерительный скрипт на кэше.

## Ограничения заранее

- 208 дней — это ~20 независимых «режимов», для lead-lag это мало.
- Универсум кэша (52 монеты) сформирован по текущей ликвидности → survivorship bias.
- Никакой информации о стакане и потоке сделок нет: только свечи. Настоящий lead-lag
  обычно живёт в секундах, а мы меряем час — если эффект есть и на часе, это уже
  другая (более медленная) причина, и её надо объяснять отдельно.
