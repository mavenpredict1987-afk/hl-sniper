# Пре-регистрация: каскад-бай — покупка обвала, удержание 12 часов

Дата: 2026-10-21, до прогона.

## Откуда гипотеза

В дашборде референсного бота модуль `cascade_buy` стоит выключенным, но с
единственной положительной цифрой среди выключенных: **+0.94% за 12 часов,
t = 2.03**. Его кода для этого модуля нет — в присланном файле реализации нет,
поэтому это не репликация, а проверка самой идеи в естественной для нас форме.
Если идея верна, она должна воспроизводиться на общих данных, а не только у
автора.

## Правило (наше, заморожено)

- вселенная: 52 монеты из кэша (все, по которым есть 5000 часовых баров);
- **событие**: закрытая свеча `h`, где падение за одну свечу
  `(close[h] − close[h−1]) / ATR14[h] ≤ −2.0` **или** падение за три свечи
  `(close[h] − close[h−3]) / ATR14[h] ≤ −3.5` (каскад);
- **вход**: по открытию свечи `h+1` (никакого взгляда вперёд);
- **выход**: ровно через 12 свечей, по открытию `h+13`;
- **размер**: равные доли, капитал 1000;
- **издержки**: тейкер 0.045% + проскальзывание 0.05% на каждой стороне
  (0.19% за круг), плюс почасовой фандинг на удержании;
- **неперекрывающиеся события**: пока позиция открыта, новые события того же
  «портфеля» игнорируются — иначе t-статистика считается по наложенным окнам и
  завышается в разы.

Два режима, оба считаются:

1. **портфель** — на каждом событии покупаем все монеты, которые в этот час
   дали каскад (равные доли). Это и есть проверка «покупай обвал» как стратегии;
2. **по монетам** — та же сделка по каждой монете отдельно, чтобы увидеть, не
   держится ли результат на одной монете.

## Метрики

- средний чистый результат сделки в % и в USD на 1000, медиана, доля прибыльных;
- **t-статистика по независимым событиям** (неперекрывающиеся окна);
- половина 1 против половины 2 датасета (устойчивость во времени);
- вклад крупнейшего события и крупнейшей монеты в общий PnL;
- просадка кривой портфеля (mark-to-market по закрытию);
- отдельно: результат без издержек (чтобы видеть, сколько съедают комиссии).

## Критерии приёмки (записаны до прогона)

Идея идёт в бумажный модуль, только если одновременно:

1. средний **чистый** результат > 0 при полных издержках;
2. t ≥ 2.0 по независимым событиям (не по наложенным окнам);
3. положительно в **обеих** половинах датасета;
4. крупнейшее событие даёт ≤ 25% общего PnL, крупнейшая монета ≤ 35%;
5. сигналов достаточно для статистики: ≥ 40 независимых событий.

Если не проходит — модуль в реестре переезжает из «нет» в «отклонён» с этой
цифрой, и в реальные деньги не идёт.

## Оговорки

- данных всего 208 дней и они покрывают один режим рынка; «обе половины» — это
  не OOS, а проверка на устойчивость;
- фандинг из кэша почасовой, но в стрессовые часы он как раз и растёт — если
  результат держится только без фандинга, это отказ;
- каскад-бай по определению ловит падающий нож: даже при положительном
  матожидании распределение будет с длинным левым хвостом. Для реальных денег
  понадобится жёсткий лимит на размер и на число одновременных позиций.
